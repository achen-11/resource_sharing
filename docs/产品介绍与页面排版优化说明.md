# Kooboo 资源共享平台：产品介绍与页面排版优化说明

日期：2026 年 11 月 5 日  
用途：交给 Gemini 理解产品、梳理信息层级，并优化现有页面排版。  
依据：本次 `kb pull` 后的当前源码；产品功能描述与排版建议分别说明。

## 1. 产品是什么

Kooboo 资源共享平台是一个面向组织内部的开发资源共享工具。团队成员把可复用的 Skill、模块包、模板片段和代码块登记到平台，补充使用说明与接入说明，经审核发布后，让有权限的同事找到、下载和复用。

它要解决三个具体问题：

- **找不到**：资源散落在聊天记录、个人目录和不同项目中，其他人不知道已有成果。
- **用不起来**：只有文件，没有适用场景、接入步骤、版本和维护人信息。
- **管理困难**：资源该给谁看、谁来审核、哪个版本已发布、何时下架，缺少统一入口。

产品的核心价值是把“找到资源 → 判断是否适合 → 获取并使用”和“登记资源 → 维护版本 → 审核发布”两条路径连接起来。

页面应呈现为清晰、安静、便于日常操作的内部工作台。资源目录是使用入口，我的资源是维护入口，审核与管理页面服务于资源治理。

## 2. 谁在使用

| 用户 | 主要任务 | 设计重点 |
| --- | --- | --- |
| 普通成员 / 资源使用者 | 搜索、筛选、阅读指南、下载资源、复制安装说明 | 快速判断资源用途，清楚找到获取入口 |
| 资源维护者 | 登记自己的资源，填写指南，创建版本，送审，维护上架状态 | 知道当前状态、下一步动作，以及修改是否已经对使用者生效 |
| 审核人 | 查看待审核版本，检查说明和文件，通过或驳回，管理上架状态 | 审核依据与操作在同一阅读路径中，避免误操作 |
| 平台管理员 | 维护分类、分配平台角色、处理资源与查看统计 | 以表格和必要操作为主，避免装饰信息挤占工作空间 |

代码中定义的平台角色为“成员、审核人、平台管理员”。资源维护者是业务身份，通常就是资源的创建者，并非另一个需要新增的角色。

账号、组织和部门来自 Kooboo。平台内的用户管理页主要分配应用角色，不负责新建组织账号或编辑组织部门。

部门资源的审核还有部门管理身份限制；实际可见数据和可执行操作由现有权限逻辑决定。Kooboo 管理员还有额外管理权限。排版调整应保留这些判定。

## 3. 平台里的“资源”由什么组成

| 信息组 | 当前信息 | 用户需要理解的内容 |
| --- | --- | --- |
| 基础信息 | 名称、一句话简介、分类、标签、维护人、更新时间 | 资源是什么，适合什么情况，由谁维护 |
| 归属范围 | 公共、部门、私有；部门范围还关联具体部门 | 谁可以看到和获取它 |
| 使用指南 | Markdown 内容和预览 | 资源怎么使用，有哪些注意事项 |
| 接入指南 | Markdown 内容和预览 | 怎么放进现有项目，需要哪些依赖和配置 |
| 快速安装说明 | 可开关的 prompt 模板、生成结果、复制操作 | 把说明交给本机 AI 环境协助接入 |
| 版本与文件 | 版本号、变更说明、分发方式、文件或外链、审核信息 | 当前获取的是哪个版本，这次改了什么 |
| 发布与使用记录 | 最新版本状态、当前发布版本、上架状态、下载次数、操作记录 | 资源现在是否可用，发布流程处于哪一步 |

Skill、模块包、模板片段、代码块是典型资源内容。目前基础信息表单没有独立的固定“资源类型”字段，分类由管理员维护多级分类树。设计方案不要自行把这四种内容做成必须填写的新字段。

两种分发方式：

- **平台上传**：上传资源包或单文件。当前业务上传服务限制为 50 MiB，支持 zip、tar/gz 等压缩包，以及部分代码和文本文件。
- **外部链接**：维护者填写外部地址，使用者打开该地址获取资源。外部站点的访问控制由其自身处理。

“快速安装”目前是生成并复制 prompt，再由使用者交给本机 AI 处理。平台没有安装进度或安装完成状态，不应把现有复制功能包装成自动安装。

## 4. 可见范围与发布状态

### 4.1 归属范围

| 范围 | 常规使用者的可见性 |
| --- | --- |
| 公共 | 已登录的组织用户可以看到符合发布和上架条件的资源 |
| 部门 | 归属部门成员可以看到符合条件的资源 |
| 私有 | 维护者本人可见；管理员按后端现有规则拥有额外管理范围 |

这里的“公共”属于组织内部共享，并不表示向未登录的互联网访客公开。

### 4.2 两种状态必须分清

**版本状态**记录送审进度：草稿 → 审核中 → 已发布 / 已驳回。被驳回的版本可按现有流程再次送审。

**上架状态**记录已发布资源是否对目录开放：在架 / 已下架。恢复上架使用现有已发布版本，不要求重新走一次审核。

例如：资源 v1 已发布且在架，维护者又创建了 v2 草稿。使用者仍获取 v1；维护者需要同时看到“最新版本 v2 · 草稿”和“当前上架 v1”。不能用一个模糊的“状态”覆盖两层含义。

目录展示当前已发布且在架的版本。新草稿不会替代当前发布版本。审核通过后，提交的版本成为当前发布版本并上架。

资源下架后从使用者目录移除，相应受控下载入口按现有规则失效；已经下载到使用者电脑的文件不会被收回。

## 5. 三条主要使用流程

### A. 找到并使用资源

1. 使用组织账号登录，进入资源目录。
2. 用名称、简介、标签或维护人关键词搜索，也可按归属和分类筛选。
3. 查看资源详情，判断用途、版本、维护人和使用方法。
4. 下载托管文件，或打开外部链接。
5. 如资源启用了快速安装，复制 prompt 交给本机 AI。
6. 如需让浏览器外的工具下载托管文件，生成有时效的 AI 下载链接。

AI 下载链接默认有效期为 72 小时，属于持有链接即可使用的临时凭证。链接过期、资源下架或对应版本不再是当前发布版本时，按后端规则失效。界面应保留复制、有效期和生成失败提示。

### B. 维护并发布自己的资源

1. 在“我的资源”点击登记资源。
2. 填写基础信息与归属，先保存资源。
3. 完善使用指南、接入指南，按需配置快速安装 prompt。
4. 创建版本，选择上传文件或填写外链，并填写变更说明。
5. 将可送审的版本提交审核。
6. 审核通过后发布；被驳回时查看意见并继续处理。
7. 后续更新创建新版本；必要时下架或恢复上架。

“先保存资源，再创建版本”是现有真实流程。可以改善引导和按钮位置，但不能只改界面就假设新资源能立即上传、送审。

### C. 审核与治理

1. 审核人在“审核台”的待审核页签查看自己有权限处理的提交。
2. 打开审核详情，查看版本、变更说明、指南及资源内容入口。
3. 选择通过或驳回；驳回需要填写原因。
4. 在“我处理过的”查看处理结果，在“已发布”中管理上下架并查看变更记录。
5. 管理员在分类管理、用户管理、使用统计中维护平台。

审核通过、驳回和上下架已有通知或操作记录能力。当前审核主要由人判断，不包含自动内容质量检测。

## 6. 页面地图

应用使用 hash 路由，下面 `/catalog` 对应站点中的 `/#/catalog`。

| 页面 | 路由 | 当前内容与动作 |
| --- | --- | --- |
| 资源目录 | `/catalog` | 关键词、归属、分类筛选；资源总数；资源卡片；进入详情 |
| 资源详情 | `/catalog/:id` | 简介与元信息、当前版本和下载、AI 下载链接、快速安装 prompt、使用指南、接入指南、已发布版本 |
| 我的资源 | `/my-resources` | 搜索、版本状态和分类筛选；资源表格；登记、编辑、送审、上下架、符合条件时删除；分页 |
| 登记 / 编辑资源 | `/my-resources/new`、`/my-resources/:id` | 基础信息、使用指南、接入指南、快速安装、版本五个页签；保存；新建版本弹窗 |
| 审核台 | `/review` | 待审核、我处理过的、已发布三个页签；审核详情、驳回、上下架和变更记录 |
| 分类管理 | `/taxonomy` | 多级分类树表格；新建根分类、子分类、编辑、排序和启停等管理操作 |
| 用户管理 | `/users` | 平台角色说明、成员搜索、部门信息、角色分配、最后活跃时间 |
| 使用统计 | `/stats` | 六项统计、热门资源、部门资源、归属分布、下载最多的用户、最近下载；管理权限下的孤立文件清理 |
| 登录 | `/login` | 产品标识、简短介绍、组织账号登录表单、校验和失败反馈 |

侧栏有六个一级入口：资源目录、我的资源、审核台、分类管理、用户管理、使用统计。管理入口按权限显示，详情和编辑页不单独增加一级菜单。

当前目录以筛选后的返回结果展示资源，数据超出返回数量时有提示；不要在纯排版方案中把它描述为已经支持无限滚动。统计页现有数据为资源总数、在架、已下架、待审核、版本总数、累计下载，以及对应分布和记录，没有现成的时间趋势图数据。

## 7. 当前视觉方向与已确认修正

视觉参考是 CPR（用户提供的 Codex Proxy 截图）：白色侧栏，浅灰蓝背景，白色圆角内容面板，深色文字，低对比表单底色，克制使用状态色和线性图标。

当前样式基线：

| 元素 | 当前基线 |
| --- | --- |
| 页面背景 | `#f5f7fb` |
| 面板 | 白色；常规圆角 20px；常规内边距 24px |
| 表单底色 | `#f2f4fa` |
| 侧栏选中背景 | `#e9eef5` |
| 主文字 / 次文字 | `#111b2b` / `#5e697c` |
| 强调色 | `#5079ed`；主操作按钮目前采用深色底 |
| 页面标题 | 桌面 24px；中等宽度 22px；手机 20px |
| 侧栏 | 常规宽度 252px；账户与通知在底部；手机改为顶部工具栏与导航抽屉 |
| 页签 | 灰底分段容器，白色选中项 |
| 字体与数字 | 系统中文无衬线字体；统计数字使用等宽字体与等宽数字 |

**2026 年 11 月 5 日，用户刚修正了两处问题：页面标题从 32px 缩小至上述尺寸；分段页签首尾内边距通过更高优先级的选择器修正。后续优化要以这版为起点，保留这两处修正的效果。**

排版偏好：避免不必要的次级标签和解释文字。优先通过对齐、分组、留白和主次关系表达结构。说明文字应帮助用户做决定，不需要给每个模块再添加一句描述。

## 8. 本次希望 Gemini 优化什么

目标是让既有功能更易理解、更容易操作，形成统一且适合真实数据密度的页面排版。以下是需要评估的方向，不代表已经完成的新功能。

| 优先级 | 页面 / 范围 | 希望解决的问题 |
| --- | --- | --- |
| 优先 | 全局框架 | 侧栏、页头、筛选、内容和页内操作建立稳定的对齐关系；留白适中；面板不要层层套用 |
| 优先 | 资源目录 | 明确名称、简介、分类、标签、归属、维护人、版本和下载数的优先级；卡片有长短内容时仍易扫描 |
| 优先 | 资源详情 | 让“这是什么、怎么获取、怎么使用”顺畅衔接；长文宽度可读；下载与复制入口明确；不被大量同级白卡片拉长 |
| 优先 | 登记 / 编辑资源 | 让基础信息、版本创建、保存和送审的关系清楚；避免在多个页签间来回寻找下一步动作 |
| 随后 | 我的资源 | 区分最新版本、当前发布版本与上架状态；表格操作适度收敛，危险操作与日常操作分开 |
| 随后 | 审核台 | 让待审内容、审核权限、版本和变更说明容易比较；详情阅读与通过 / 驳回动作衔接清楚 |
| 随后 | 分类与用户管理 | 树形缩进、表格行和操作列清楚；角色说明与权限代码可按需展开，避免抢占成员列表空间 |
| 随后 | 使用统计 | 六个指标与不同统计表格分出层次；维护操作放在合适位置，避免与日常数据阅读竞争 |
| 统一收尾 | 登录、通知、弹窗与移动端 | 保持同一视觉语言，覆盖长名称、多标签、空数据、无搜索结果、加载失败和小屏操作 |

请特别关注：

- 主要工作区在常见笔记本宽度下可用，超宽屏保持合理阅读宽度。
- 目录用卡片、管理用表格是目前的主要模式，可优化排列与密度。
- 页面主要动作、行内操作、危险操作有清楚层级。
- 搜索和筛选之后的结果状态可理解，空状态能说明用户下一步可以做什么。
- 状态同时有文字含义，不能仅靠颜色区分。
- 手机端筛选能换行，导航可关闭，表格在容器内滚动，关键操作可触达。
- 长指南、长资源名、多部门和多标签不会破坏布局。
